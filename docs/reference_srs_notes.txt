Operations
1. System Operations
Login / registration and role-based redirection to Admin or Citizen view.
JWT-based authentication with bcrypt password hashing.
Receive pH, turbidity, TDS and temperature readings from ESP32-S3 over Wi-Fi using HTTP/JSON.
Validate incoming sensor payloads before processing and storage.
Compare readings against configurable safe-range thresholds.
Generate an alert when a configured threshold is breached.
Store users, node/location, readings, alerts, notifications, image checks and thresholds in MongoDB.
Send SMS notifications to the authority and registered residents when an alert is generated.
Provide live readings, trends, alert history and node location through the web application.
Support water-image upload and AI-based safe/unsafe screening with a confidence value.

System Architecture
Sensing layer: four sensors connected to ESP32-S3, sampling at fixed intervals; regulated mains adapter.
Communication layer: Wi-Fi (HTTP/JSON) is the only link between the node and backend.
Application layer: Node.js/Express handles authentication, payload validation, threshold checks and alert generation; it also calls the SMS gateway and AI image module.
Data layer: MongoDB stores users, node/location, readings, alerts, notifications, image checks and thresholds.
Presentation layer: React web app shows live data, trends, alerts and Leaflet map and provides the image-upload page.

Scope and Constraints
In Scope
Single ESP32-S3 prototype node.
pH, turbidity, TDS and temperature sensing.
Wi-Fi/HTTP-JSON communication.
MERN-based web platform.
Configurable thresholds and automatic alerts.
SMS notifications to authority and registered residents.
Leaflet/OpenStreetMap node location.
Citizen/Admin water-image screening with confidence.
Historical readings, trends, alert history and CSV/report export.
Out of Scope / Constraints
Initial prototype is single-node.
LoRaWAN is not part of the current communication path.
Solar/battery deployment is not part of the current prototype; the node uses regulated mains power.
Edge/TinyML inference is not part of the current planned implementation.
Exact AI implementation is not fixed; hosted vision API or trained image classifier will be selected.
Large-scale multi-node production deployment is outside the current prototype scope.
Requirement Acceptance Criteria
Four sensors can be read at fixed intervals after calibration.
Valid readings can be transmitted to and accepted by the Express API.
Validated readings are stored in MongoDB.
Dashboard displays current readings and historical trends.
Threshold breach creates an alert.
Alert information reaches dashboard and configured SMS recipients during testing.
Admin can configure thresholds and SMS recipients.
Image upload produces the specified screening output after AI module integration.
Authentication and role-based access work as specified.
Planned test cases are executed and documented after implementation.
